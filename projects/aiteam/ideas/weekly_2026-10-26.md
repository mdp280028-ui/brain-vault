## Stop re-logging slug_already_shipped skips: 116 rows/14d still flooding audit_log

**Score:** 3.799999999999999823 · **Build:** 1.5h · **Impact:** `medium` · **Slug:** `ship-to-site-skip-dedup-recurrence`

**Signal:** `diagnose.e_repeated_failures_14d[0] (ship_to_site_skipped, n=116) and diagnose.a_top_actions_7d (ship_to_site_skipped rows)`

ship_to_site_skipped is the single largest repeated-failure row in e_repeated_failures_14d (116 events), and its example payload is reason=slug_already_shipped for voicenation-vs-patlive, a slug already in APPROVED_GUIDE_SLUGS. The same slugs (asbestos-abatement-near-me, asbestos-abatement-process, asbestos-air-quality-test and others) each appear twice in a_top_actions_7d. Estimated build is about 1.5 hours of Claude Code work in ship-to-site/ship.sh. Output: diagnose section e shrinks to real failures, and the operator spends less time triaging a false alarm. Estimated saving is about 0.5 operator hours/week of diagnose-noise triage, plus a cleaner repeated-failure table for this agent's own synthesis.

Downside: this is a near-duplicate of the pending ship-to-site-skip-dedup proposal from 2026-05-24, which has never been actioned. The mechanism differs only if it also drops the log for already-shipped slugs rather than merely deduplicating. If the original is simply never built, this one will sit unbuilt too. Cost if wrong: about 1.5 hours of build time, and suppressed skip rows could hide a genuine ship-state bug.

## Tombstone slugs after repeated srcver_fail so they stop burning verifier and writer calls

**Score:** 3.600000000000000088 · **Build:** 3.0h · **Impact:** `medium` · **Slug:** `srcver-fail-slug-tombstone`

**Signal:** `diagnose.e_repeated_failures_14d[1] (srcver_fail, n=33) and diagnose.a_top_actions_7d (srcver_fail for brex-alternatives and best-field-service-management-software-for-small-business, n=6 each)`

srcver_fail fired 33 times in 14 days (e_repeated_failures_14d[1]). In a_top_actions_7d two slugs carry 6 failures each: best-field-service-management-software-for-small-business and brex-alternatives. Six identical failures on one slug in seven days means the loop is retrying content that source verification will keep rejecting. Each retry spends ssg-writer and ssg-auditor calls, which are the top two cost agents this week at $3.96 and $2.91 (b_top_cost_agents_7d).

The change is a failure counter per slug: after 3 consecutive srcver_fail rows, write the slug to a tombstone file, skip it in the drafter, and send one Telegram line asking the operator to rewrite or drop it. Estimated build is about 3 hours in the drafter and ship path. Output: the two stuck slugs stop consuming spend and the operator gets one actionable alert instead of a silent loop.

Savings are bounded by the evidence: 12 repeat failures in 7 days across two slugs. If each re-run costs roughly the auditor per-call average of $0.32 (2.91 over 9 calls), that is roughly $3.80 per week or about $16/month. That is an estimate from average cost, not a measured per-slug cost.

Downside: this is the same mechanism as the pending config-synth-stuck-slug-tombstone and assignment-draft-validation-tombstone proposals, applied to a different failing stage. A tombstoned slug that was only transiently failing, for example a flaky source fetch, gets dropped from the queue until the operator clears it. Note also that the example payload is a negative-control test run (ssg-repair-test-1-negctl), so part of the 33 may be test traffic rather than production slugs.
