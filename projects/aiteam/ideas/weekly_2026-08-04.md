## Add npm lockfile integrity check to SSG deploy pipeline after Shai-Hulud worm compromise

**Score:** 3.799999999999999823 · **Build:** 1.5h · **Impact:** `medium` · **Slug:** `npm-supply-chain-lockfile-audit`

**Signal:** `scan.hackernews[2] (aikido.dev Shai-Hulud advisory, 2026-08-04)`

On 2026-08-04 the keyv/flat-cache/cacheable package family (868 packages, 2B+ monthly installs) was compromised via a hijacked maintainer GitHub account, injecting a preinstall credential-stealing worm that propagates to any downstream project running npm install against a poisoned version. The SSG content site (diagnose.j_repo_freshness_days shows ssg_content_days=0, actively touched) runs a Node toolchain and is exposed to this exact class of attack if any transitive dependency on keyv, flat-cache, file-entry-cache, cacheable-request, or cache-manager exists in its lockfile — these are extremely common transitive deps (file-entry-cache alone is pulled in by eslint's cache layer).

The fix is a one-time audit plus a permanent pre-deploy gate: grep the SSG repo's package-lock.json or npm ls for the compromised package names and pinned-bad versions (keyv 6.0.0, flat-cache 6.1.24, file-entry-cache 11.1.6, cacheable-request 13.0.20, cacheable 2.5.1, and the others listed in the aikido.dev advisory), and if found, pin to a pre-compromise version or remove the dependency chain. Add a 10-line check to run-batch.sh or the deploy script that fails the deploy if any of these package@version pairs appear in the lockfile, so future dependency bumps can't silently reintroduce a compromised version before the community fully purges it from the registry.

Prevents credential exfiltration (npm tokens, and per the advisory, broader environment secrets) from a Mac Mini that also holds Anthropic API keys and Telegram bot tokens in its environment. Estimated frequency: unknown — this is the first observed incident of this scale referenced in this agent's scan, but supply-chain worms of this pattern (Shai-Hulud has had prior waves) recur every few months per community reporting. Impact if it happens: full credential compromise across every service the Mac Mini's environment variables touch, requiring a full secrets rotation (~4-6h) and no confidence the box is clean without a rebuild.

If this is wrong, the cost is: ~1 hour spent grepping a lockfile that turns out to be clean, plus a permanent CI check that adds a few seconds to each deploy — low-cost even if the SSG repo has zero exposure.
